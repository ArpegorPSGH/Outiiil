## Build & Verify Commands

### Python syntax check
```bash
python -m py_compile scripts/lib/build_bundle.py scripts/release.py scripts/test_prod.py scripts/lib/release_common.py
```

### Build the runtime bundle (dev)
```bash
python scripts/lib/build_bundle.py
```
Generates `dist/runtime.js`, `dist/runtime.css`, `dist/version.json` (with SHA-256 + socle_hash), and `dist/images/`.

Use `--version X.Y.Z` to override the version (useful for test pre-deployment):
```bash
python scripts/lib/build_bundle.py --version 3.22.27-test.1
```

Use `--update-url URL` to override the BASE_UPDATE_URL used for socle hash computation (required for test builds pointing to a different GitHub Pages repo):
```bash
python scripts/lib/build_bundle.py --version 3.22.27-test.1 --update-url https://owner.github.io/Outiiil-test/dist/
```

### JSON validation
```bash
python -c "import json; json.load(open('manifest.json')); json.load(open('bundle_sources.json'))"
```

### Release (requires clean git state + gh CLI for GitHub releases)
```bash
python scripts/release.py
```

### Pre-deployment test (test branch simulation)
```bash
python scripts/test_prod.py [--verify] [--test-repo Outiiil-test]
```
Simulates the full release workflow on a **test branch/repo** without creating a Git tag or GitHub release. Generates a production-mode zip socle (`DEV_MODE=false`) pointing to the test branch, and deploys `dist/` to a secondary GitHub repo (default: `Outiiil-test`) with GitHub Pages enabled. Requires a secondary repo with GitHub Pages configured on its `gh-pages` branch.

## Architecture Overview

The extension uses a **two-layer architecture**:

1. **Static bootstrapper** (installed once):
   - `background.js` — Service worker with generic Chrome API RPC dispatcher and update coordinator
   - `bridge.js` — Content script (isolated world) that bridges postMessage between runtime and background

2. **Dynamic runtime** (updated from GitHub Pages):
   - `runtime.js` — User script registered via `chrome.userScripts.register()` with `world: "MAIN"`
   - `runtime.css` — Styles for the runtime
    - `version.json` — Version info, SHA-256 hash, image list

## Browser Compatibility

- `chrome.userScripts.register()` with `world: "MAIN"` is supported in Chrome 120+, Firefox 121+ (MV3), Edge, and Brave.
- In Chrome, users must enable the userScripts toggle at `chrome://extensions/`.
- In Firefox, `userScripts` is an optional permission requested at runtime via `chrome.permissions.request()`.
- `world: "MAIN"` means the user script shares the page's JavaScript context. Host pages can see and access the injected code.
- Communication from MAIN world (runtime.js) to background (service worker) goes through `window.postMessage` → bridge.js (isolated content script) → `chrome.runtime.sendMessage`.
